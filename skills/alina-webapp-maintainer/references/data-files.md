# Βάση και PDF παραγωγής

Διάβασε αυτό το αρχείο μόνο όταν ο χρήστης ζητά εργασία στα live δεδομένα. Ο κατάλογος είναι `/var/www/enlogic.gr/other/alinas-exams/data/`. Η βάση είναι `alina_tracker.db` και τα PDF είναι στο `documents/`. Τα αρχεία ανήκουν στην ομάδα `alina-exams`, στην οποία συμμετέχει ο `mas`. Για αρχεία χρησιμοποίησε δικαιώματα `660` και για υποφακέλους `2770`, ώστε να μπορούν να εργαστούν και ο `mas` και η υπηρεσία. Έλεγξε με `stat` και με δοκιμή ανάγνωσης/εγγραφής όπου χρειάζεται. Η SQLite μπορεί να δημιουργήσει νέο `.db` με `640` ακόμη και μέσα σε κοινό φάκελο: ο ιδιοκτήτης του νέου αρχείου πρέπει να εκτελέσει `chmod 660` πριν το χρησιμοποιήσει η υπηρεσία. Μην αλλάζεις δικαιώματα σε γονικούς φακέλους ή άσχετα αρχεία.

## PDF

- Για νέα εξέταση, προτίμησε τη φόρμα της εφαρμογής: δημιουργεί και τη συσχέτιση στη SQLite. Η απλή αντιγραφή ενός PDF στο `documents/` **δεν** το εμφανίζει στην εφαρμογή. Για υπάρχουσα εξέταση, έλεγξε το `document_path` στη βάση πριν αντικαταστήσεις ή σβήσεις το αντίστοιχο αρχείο.
- Μετέφερε PDF μόνο μέσω προστατευμένης σύνδεσης SSH/SFTP. Για άμεση αντικατάσταση, κράτησε αντίγραφο, ανέβασε σε προσωρινό αρχείο στον ίδιο κατάλογο, έλεγξε τύπο και μέγεθος, όρισε group write, και μετά κάνε μετονομασία στο τελικό όνομα. Μη δημοσιεύεις περιεχόμενο ή ονόματα ασθενών στο chat.
- Πριν από διαγραφή, βεβαιώσου ότι το PDF δεν αναφέρεται πλέον από εγγραφή. Αν ο χρήστης ζητά διαγραφή εξέτασης, προτίμησε τη ροή της εφαρμογής που χειρίζεται μαζί εγγραφή και αρχείο.

## Αντικατάσταση ολόκληρης βάσης

1. Εξακρίβωσε ότι η νέα βάση είναι συνεπές SQLite snapshot, ότι το `PRAGMA integrity_check` επιστρέφει `ok`, και ότι έχει το schema που περιμένει ο τρέχων κώδικας. Αν προέρχεται από ζωντανή SQLite βάση, χρησιμοποίησε το SQLite backup API αντί για απλή αντιγραφή ανοιχτού `.db` αρχείου. Έλεγξε επίσης ότι τα PDF που αναφέρει η νέα βάση θα υπάρχουν στο `documents/`.
2. Ετοίμασε προστατευμένο αντίγραφο επαναφοράς της τρέχουσας βάσης και των αντίστοιχων PDF. Σταμάτησε την υπηρεσία με `sudo -n /usr/bin/systemctl stop alina-exams.service` και επιβεβαίωσε ότι σταμάτησε. Μη σβήσεις τυχόν SQLite `-wal` ή `-shm` αρχεία χωρίς να ελέγξεις τη λειτουργία της βάσης.
3. Ανέβασε τη νέα βάση ως προσωρινό αρχείο στον ίδιο κατάλογο, με group `alina-exams`. Εκτέλεσε `chmod 660` στο προσωρινό αρχείο και επιβεβαίωσε με `stat` ότι η υπηρεσία θα μπορεί να γράψει. Έλεγξε ξανά την ακεραιότητα του προσωρινού αρχείου. Αντικατάστησε τη live βάση μόνο αφού περάσουν αυτοί οι έλεγχοι. Μετέφερε μαζί τα PDF που απαιτεί η νέα βάση.
4. Ξεκίνα την υπηρεσία με `sudo -n /usr/bin/systemctl start alina-exams.service`. Έλεγξε `systemctl is-active`, `GET /health` τοπικά, το δημόσιο URL, τα αναμενόμενα πλήθη εγγραφών και μία πραγματική διαδρομή χρήσης με τον κάτοχο του λογαριασμού. Σε αποτυχία, σταμάτησε την υπηρεσία, επανάφερε το αντίγραφο βάσης/PDF και ξεκίνα ξανά. Ανακοίνωσε καθαρά αν ολοκληρώθηκε ή αν έγινε επαναφορά.

Η εφαρμογή διαβάζει τα δεδομένα από το `data/`, αλλά ο Python server εξυπηρετεί μόνο ρητά καταχωρισμένα στατικά αρχεία και authenticated API routes. Ο Nginx έχει ρητό κανόνα 404 για το `/other/alinas-exams/data/`. Έλεγξε ότι το `www-data` δεν έχει πρόσβαση και ότι ένα HTTP αίτημα προς `/other/alinas-exams/data/alina_tracker.db` επιστρέφει 404.
